# Chaos backend

This directory contains the Convex schema, public functions, internal functions, HTTP routes and scheduled jobs. Runtime bindings in `_generated/` are generated by the Convex CLI; keep those bindings available to the application and tests.

## Changing backend behavior

- Define argument validators for every function. Use internal functions for work that must not be exposed to callers.
- Derive authenticated identity on the server and check resource permissions before reads or writes. Never trust a caller-supplied account ID as authorization. See [authorization](../docs/security-authorization.md) and [identity verification](../docs/identity-verification-policy.md).
- Bound list queries with indexes and pagination. Return only fields the caller may see; answer keys and private source material have separate disclosure rules.
- Keep existing stored content compatible. Document additive schema changes and resumable migrations in [migrations](../docs/migrations.md).
- Preserve transaction boundaries when updating related state. Test rejected access as well as successful requests.

## Checks and operations

Run `pnpm typecheck` and `pnpm test:integration` from the repository root. Integration tests use synthetic data and do not require a live deployment. See [tests](../tests/README.md), [self-hosting](../docs/self-hosting.md), [data lifecycle](../docs/data-lifecycle.md) and [administration](../docs/admin-operations.md).

Deployment changes can affect real stored data. Review the target environment and migration requirements before using the Convex CLI to deploy. The framework reference is available at <https://docs.convex.dev/>.
