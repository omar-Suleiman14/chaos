# Chaos + Max: features and fixes to ship

Planning snapshot: September 26, 2026. No product implementation is included.

Reviewed the complete issue inventory returned by GitHub for Chaos (224: 223 open, 1 closed) and Max (151: 124 open, 27 closed), including issue descriptions and available comments for triage. Release parents and overlapping work are consolidated below. This is a prioritized proposal, not a claim that every open issue still reproduces, a competitor parity certification, or a replacement for the GitHub roadmap.

## Product goal and release order

Max is the local-first workspace for pages, databases and workflows. Chaos is the public quiz/form authoring, publishing and response service. Together they should support: create a form from a Max database, review it, publish it through Chaos, collect responses, and use approved results in Max. Each product must also work independently.

Recommended order: dependable AI-free Chaos Quiz and dependable Max desktop; complete Chaos Forms; connect Max and Chaos; add advanced forms and workspace features. Mobile apps, extra stores, direct device sync, QTI and H5P are later work. Signing remains a gate for whichever desktop distribution channels are actually selected for launch.

## Priority 0 — release-critical fixes

- **Remove AI from Chaos completely.** Remove the quiz generator, editor chat, progress/cancellation surfaces, AI-only admin settings, usage counters, quotas and upgrade copy. Retire generation/editing endpoints, jobs and scheduled work; remove OpenRouter configuration and unused dependencies. Remove PDF/OCR only where it exists solely for AI. Preserve ordinary quizzes previously generated by AI, their answers, scores and public URLs. Decide retention/export of historical job/source data before any deletion. Verify normal creation, editing, publishing, playing, grading and export work without AI credentials. This is the owner's new direction; it supersedes AI expansion work.
- **Make drafts safe.** Autosave during continuous editing; recover after refresh or connection loss; show accurate unsaved/saving/saved/failed states; prevent server updates from overwriting local edits. Done means the interrupted-save and recovery journeys preserve the draft. [Draft safety](https://github.com/omar-Suleiman14/chaos/issues/34).
- **Make publishing deliberate.** Start new content as a private draft, allow incomplete draft saves, and validate all publication requirements on the server. Show all blockers together. Preserve previously published content. [Publication validation](https://github.com/omar-Suleiman14/chaos/issues/35).
- **Finish every existing quiz type end to end.** Author, edit, reorder, save and reload MCQ, true/false, multi-select and written questions without losing fields. Define partial credit and explain keyword grading honestly. Keep hints, results, CSV and printable answer keys consistent and permission-aware. [Quiz completeness](https://github.com/omar-Suleiman14/chaos/issues/22).
- **Reverify security and grading before release.** Confirm owner/admin permissions, answer secrecy, ban enforcement, non-elevated account defaults, safe anonymous sessions, replay resistance and rejection of cross-quiz answers. Several safeguards already exist locally; this is verification and remaining fixes, not a blanket claim they are missing. [Security baseline](https://github.com/omar-Suleiman14/chaos/issues/3).
- **Protect Max data through upgrades and restores.** Failed migrations and damaged backups must leave the healthy workspace intact. Make restore consequences clear; verify pages, records, relations, attachments and workflows after restart. [Migration recovery](https://github.com/omar-Suleiman14/max/issues/56), [backup UX](https://github.com/omar-Suleiman14/max/issues/57).
- **Finish essential usability.** Keyboard access, non-drag alternatives, focus restoration, reduced motion, mobile respondent layouts, Arabic/RTL behavior, and useful loading, empty and failure states. Prioritize completing real tasks over redesigning every screen. [Chaos accessibility](https://github.com/omar-Suleiman14/chaos/issues/36), [Max accessibility](https://github.com/omar-Suleiman14/max/issues/76).
- **Prove the selected release journeys.** Run create → edit → publish → respond → review → export for Chaos, and create → edit → backup → restore → restart for Max. Include supported browsers/platforms, permission failures and interrupted networks. Verify documentation against the release build and measure performance before optimizing. [Chaos release checks](https://github.com/omar-Suleiman14/chaos/issues/65), [Max release checks](https://github.com/omar-Suleiman14/max/issues/148).

## Priority 1 — forms that people can actually use

These features belong in Chaos and are exposed from Max through integration. Max's existing local Form view should continue to create local records.

- **One builder with Quiz and Form modes.** Forms have no score, correct answer or grading. Preserve existing quiz data and URLs while generalizing the model.
- **Complete form fields.** Short/long text, single/multiple choice, dropdown, number, email, phone, URL, date, time, rating and labelled numeric scale.
- **Structure and validation.** Sections, headings, descriptions, required fields, text-length rules, numeric ranges and selection limits; validation on both client and server.
- **Useful public forms.** Anonymous response links, a mobile-friendly flow, progress, clear confirmation, opening/closing schedules with explicit timezones, and honest response/attempt limits.
- **Preview and stable publication.** Preview never creates a real response; responses stay attached to the published version answered, even after later edits.
- **Complete response management.** Search, filters, pagination, response detail, deletion, useful charts and export with stable field/revision identifiers. Preserve dates, decimals, multilingual text and multi-select values.
- **Two practical presentations.** A straightforward full form and a one-question-at-a-time flow for conversational forms. The latter is an explicit product proposal; do not assume the existing Minimal experience specification already provides it.
- **Conditional flows.** Branching, skip logic, safe response piping, prefills and hidden fields with clear trust rules. Validate broken references and loops before publishing; never execute arbitrary expressions.
- **Share and reuse.** Templates, duplicate/remix, QR links and safe embeds, with one coherent share surface.
- **Uploads with defined limits.** Decide supported file types, size/count limits, storage, access and retention before promising file-upload support.

Backlog basis: [Forms](https://github.com/omar-Suleiman14/chaos/issues/75), [generic response model](https://github.com/omar-Suleiman14/chaos/issues/66), [analytics](https://github.com/omar-Suleiman14/chaos/issues/114), [logic](https://github.com/omar-Suleiman14/chaos/issues/125), [sharing](https://github.com/omar-Suleiman14/chaos/issues/156).

## Priority 1 — Chaos and Max integration

- **Create Form / Create Quiz / Open in Chaos.** Start from selected Max content and preview exactly what leaves the workspace. Map structured fields and questions explicitly; arbitrary prose does not become a quiz automatically after AI removal.
- **Database-to-form mapping.** Map selected Max properties to supported Chaos fields, including labels, options, required rules and order. Explain unsupported types before sending. This mapping UX is a proposed refinement of the existing import/provider work.
- **Review before publication.** Imported content is a Chaos draft. Return its identifier, URL, mode and publication state to Max; retain a safe source association without leaking local paths or unrelated content.
- **Explicit connection permissions.** Connect/disconnect, scoped credentials, secure storage, revocation and clear reconnect states. Each product remains usable when the other is unavailable.
- **Reliable delivery.** Versioned generic API, validation, idempotent creation, rate limits, retry/backoff and recoverable partial sends that never alter Max's source data.
- **Results inside Max.** Show compact, permissioned summaries with freshness and unavailable/deleted states. Keep Chaos as the source of truth for responses.
- **Optional events.** Signed webhooks, replay protection, secret rotation and delivery history; polling/manual refresh remains available because a local Max desktop cannot be assumed reachable.
- **New proposal: selected responses become Max records.** Add an opt-in field mapping and import action for a chosen destination database, deduplicated by response identifier. Define access, edits, deletions and retry behavior. This exceeds the current summary-only contract and must be designed explicitly; never silently mirror the entire response database.
- **New proposal: notifications and follow-up workflows.** Optional new-response notifications and explicit Max workflow triggers once approved responses arrive. Make failures visible and repeat delivery safe.

Backlog basis: [Chaos integration foundation](https://github.com/omar-Suleiman14/chaos/issues/168), [Max provider](https://github.com/omar-Suleiman14/max/issues/135), [summary boundary](https://github.com/omar-Suleiman14/max/issues/136), [failure handling](https://github.com/omar-Suleiman14/max/issues/137).

## Priority 2 — Max as a practical Notion alternative

- **Dependable page editing.** Selection, Backspace deletion, undo/redo, paste, nesting, slash commands, image drop/resize, covers, icons and narrow layouts. Preserve page IDs, links and unsupported blocks through any editor migration.
- **Portable page content.** A versioned MaxDocument/MaxBlock format owned by Max, with a replaceable editor adapter. Complete the BlockNote fit/licensing evaluation before migration.
- **Reliable databases.** Preserve existing views, typed properties, relations, formulas, rollups, saved filters and linked databases. Verify completed database work rather than rebuilding it.
- **Better navigation and discovery.** Predictable sidebar behavior, backlinks/outgoing links, keyboard search ranking, consistent menus and useful persisted graph controls.
- **Useful automation.** Complete visual workflow authoring, schema validation, a no-write preview and understandable failure details. Add reusable, versioned Blueprints and configurable quick actions.
- **Publishing selected pages.** Show exactly what becomes public; support static export and selected hosting paths. Unrelated pages, linked private records and attachments must stay private.
- **Trustworthy backup and multi-device sync.** Keep them distinct. Version backups and prove restoration; add sync with explicit conflicts, attachment handling and deletion rules that prevent an offline device from resurrecting deleted content.
- **New proposal: migration into Max.** A guided Notion/Markdown/CSV import with a preview, property mapping and a report of unsupported content, plus portable export. This is an adoption priority, not an existing confirmed migration capability.
- **New proposal: team-workspace scope.** Define invitations, permissions, comments and concurrent editing if the target includes teams. The current sync plan is single-user multi-device sync; it does not establish Notion-style team collaboration.

Backlog basis: [pages/editor](https://github.com/omar-Suleiman14/max/issues/13), [completed database milestone](https://github.com/omar-Suleiman14/max/issues/12), [workflows](https://github.com/omar-Suleiman14/max/issues/14), [publishing](https://github.com/omar-Suleiman14/max/issues/18), [sync](https://github.com/omar-Suleiman14/max/issues/19).

## Separate distribution and later work

- **Signing and desktop delivery:** signed/notarized direct macOS builds; channel-aware updates; Windows MSIX/Store and direct-installer verification; safe Linux DEB/Flatpak install/uninstall. Choose initial channels, then add Homebrew, more stores and listing automation. Mac App Store compatibility remains a separate review, not an assumed approval. [Desktop distribution](https://github.com/omar-Suleiman14/max/issues/15).
- **Additional apps:** mobile offline editing, attachments and sync after the shared contracts and sync behavior are proven. Keep local use account-optional. [Mobile](https://github.com/omar-Suleiman14/max/issues/20).
- **Later extensions:** direct device sync, additional respondent experiences, question banks/pools, advanced learning features, QTI and H5P research. They should not delay the first useful forms integration.
- **Self-hosting:** retain as a planned supported route, with a clean-install and backup/restore proof before claiming support. It can be a separate delivery milestone from the first hosted release.
- **Competitor migration proposal:** investigate Google Forms, Microsoft Forms and Typeform import/export paths and their supported formats/APIs at implementation time. Do not promise automatic full-fidelity migration without testing real exported examples.

## AI roadmap changes and evidence limits

The AI removal direction supersedes Chaos AI generation/editing improvements (30–32), AI 2.0 (138–155 where AI-specific), and self-host AI configuration (196). Reassess PDF/OCR/source-document work (33, 145–148) for a useful non-AI import purpose before retaining it. Learning objectives or other independent non-AI concepts may remain later features. Remove AI dependencies from release criteria, creation flows, health checks, documentation and integration descriptions. No GitHub issues were changed or closed in this task.

Local evidence shows Chaos already has CI, tests, an AGPL license, authorization helpers, non-elevated defaults and grading replay/cross-quiz guards despite related open issues. Its README still contains older defect claims. Max has 27 closed issues, including the database milestone; its README and issue states also disagree about cloud-backup readiness. Max's open editor-polish item reports implementation in a PR. These require acceptance verification, not automatic reimplementation.

The repository inspection here was a planning spot-check. No product test suites, packaged Max build, live deployment, competitor parity test or production audit ran. Max source was not checked out or modified. The article URL could not be fetched; its user-supplied full text was used to update the two local agent guidance files. Model-specific availability, pricing and switching claims were not adopted as verified facts.
