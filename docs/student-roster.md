# Students privacy and scale
Validated lesson study starts, completed responses and live joins add relationships prospectively. Existing historical responses are not silently backfilled. Signed-in-required forms link real accounts; anonymous forms and live games stay guests even when the browser is signed in. Roster records contain display context, not answers or grades. Guest labels identify interactions, not verified distinct people.

Creators can page through their private roster. Account student Cards are private by default. A student's Card appears on a teacher's public page only after the student opts in, either for that teacher (`set_student_card_visibility`, the checkbox on the teacher's Card) or for every teacher (settings, the card form, `set_student_card_preferences`). Relationships recorded before this policy stay private until the student chooses: neither the `publicVisible` default on older rows nor a global setting saved by the old card form, which always submitted its default, counts as consent. No guest public profiles are created. A global opt-out wins over every opt-in. Counts appear only in the private roster. Cursor queries are bounded to 48 records per request; the grid renders only visible rows and a small buffer, automatically fetching subsequent pages without a total student ceiling.

Public pages show students in the floating card areas beside the teacher, including the selected author in the carousel. There is no total student cap: scrolling loads more cursor pages automatically, while only visible cards and a small buffer mount. The private dashboard retains its paginated roster.

MCP `list_my_students` is categorized as individual information. `get_student_card_visibility` and `set_student_card_visibility` affect only the authenticated student's existing relationship. `list_public_student_cards` returns only account Cards whose students opted in, with a default page size of 24 and no private context. `list_public_authors` and `get_public_card` expose public Card fields. `set_author_listing_visibility` changes only the connected author's directory preference. The fan interaction remains in the browser; MCP can return the author Cards and their URLs, but does not control the visual animation.

MCP `get_student_card_preferences` and `set_student_card_preferences` access the global setting; `customize_my_card` accepts `showStudentCards`, including during a skipped onboarding. Consent is recorded explicitly: `authorStudents.publicHidden` is `false` for a per-teacher opt-in and `true` for a per-teacher opt-out; `users.studentCardsPublic` is the global opt-in and `users.hideStudentCards` the global opt-out. `publicVisible` is retained for compatibility and is not read as consent.
