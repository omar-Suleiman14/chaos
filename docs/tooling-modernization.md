# Tooling and data-path maintenance

The project targets Node 24 and uses the official Microsoft TypeScript 7 native
compiler (`typescript`, platform binaries selected by pnpm). Next's
`experimental.useTypeScriptCli` avoids the retired JavaScript compiler API.
The editor regression test uses Babel syntax parsing and Vite's existing
transformation pipeline instead of the old TypeScript API.

pnpm is pinned to 12.10.1 in the manifest, CI and Docker. Next remains on stable
16.x; React and React DOM remain paired on 19.x. Convex, MCP SDK, Vitest and
Playwright already matched stable registry releases when audited. MCP updates
are separate weekly Dependabot PRs so larger groups cannot delay them. The old
MCP release-age exception has been removed. Next 16.4.0's exact release-age
exceptions were generated by pnpm for this upgrade.

Next 16.4.0's Turbopack build failed resolving Google font asset queries in this
application. Production builds temporarily use webpack; reassess this workaround
when updating Next. Native TypeScript checking remains enabled in both paths.

## Lint and unused code

`pnpm lint` runs Oxlint for general JS/TS/React/accessibility checks and ESLint
only for the official Next and Convex rules. Babel parses the framework pass
without depending on the TypeScript 6 compiler API. Existing findings from rules
newly introduced by Oxlint are warnings; other correctness checks are errors.
The existing mount-effect exemption remains. Prettier remains the formatter.

`pnpm knip` reports unused files, dependencies, exports and types. CI runs
`pnpm knip:check`, which fails new findings. `knip-baseline.json` records existing
unused exports/types only, without line numbers; files, dependencies and unresolved
imports cannot be baselined. Remove reviewed dead exports incrementally and run
`node scripts/knip-check.mjs --update` to shrink the baseline. Review baseline
changes alongside code. The audit removed six unused files, unused direct
`@types/katex` and `axe-core` dev dependencies, and declared `server-only` directly.
`shadcn` is retained as a manual CLI and `tw-animate-css` as a CSS import.

## Auth and subscriptions

Hosted Clerk and self-hosted Better Auth remain separate adapters. Application
hooks expose `UserSession`, `AuthSession` and `AccountActions`; provider SDK user
objects are reduced to the fields the application consumes. Account controls use
`useAccount` rather than a provider-named hook. Provider-specific sign-in and MCP
integration code remains at the integration boundary.

New live-game question snapshots live in `liveGameContent`; game documents carry
only their reference and question count. Old inline rooms remain readable without
a migration. Snapshot answer keys remain server-only until reveal. Host scene
and activity subscriptions are separate: answers and joins update small counts,
standings and distributions without resending the question/options/theme payload.
State and question index guard the client merge against cross-phase responses.
The ended player podium reads three indexed rows rather than the entire roster.

Legacy quiz questions use an index including quiz, soft-deletion status and order.
Reads reject more than 500 active questions rather than silently truncating grading
data. The classic quiz list is bounded to the newest 200 entries; modern forms
use a paginated library. Elevation propagation processes 50 quizzes per batch,
and superseded jobs stop. Admin team counts are bounded to the enforced 100 member
and 100 resource limits. Student rosters, completed quiz attempts and game listings
already use bounded/indexed reads.

Published lesson adapter/SEO transformations and course reads already run inside
cross-request Next caches in `lib/learn/server.ts`, with React request deduplication;
those caches are retained. The browser quiz answer queue and saving state remain.
BlockNote, Zod 4, PostHog, Mermaid, KaTeX and fflate remain in use. No additional
runtime or service is introduced.
